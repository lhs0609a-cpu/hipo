# HIPO 거래 기능 구현 — 2026-09-22

HIPO 사람 주식을 PO로 거래하는 내부 시장을 기준으로 구현했습니다. 실제 증권사 계좌 연결이나 국내 주식 주문 전송 기능은 아닙니다.

## 변경 사항

- 실제 미체결 잔량을 가격별로 집계하는 호가창. 가짜 호가 생성 제거.
- 시장가·지정가·손절·익절·스탑리밋 주문, 부분 체결, 취소, 지정가 정정.
- 지정가 정정은 기존 체결을 보존하고 잔량에 새 주문 순서를 부여.
- 시장가는 실제 상대 주문만 체결하고 나머지를 취소. 매수자가 없는 매도로 PO를 생성하던 경로 제거.
- 주문 가능 PO·주식 수량 조회, 대기 주문을 고려한 추가 주문 검증, 동일 계정 간 체결 방지.
- 만료 주문 제외, 종목별 가격제한폭과 거래정지·서킷브레이커 상태 확인.
- 잔고·보유량·거래 기록·주문 상태·봉 데이터를 한 트랜잭션에서 처리. 커밋 뒤 실시간 알림 전송.
- 체결 기반 분봉·일봉, 캔들/선 차트, 거래량, 이동평균, 봉별 OHLC 조회.
- 기본 매수·매도와 기존 주문 API를 같은 엔진으로 연결. 신규 발행분 매수는 별도 표시.
- 시장 목록·정렬·시장 통계의 API 응답 연결 수정.
- 관심종목 저장·분류, 목표 가격 알림의 데이터 필드와 실제 모니터링 규칙 연결.
- 주문·호가·상세·차트 5초 갱신, 부분 체결/취소 내역 표시, 매수자·매도자별 거래 구분.
- IPO·Pre-IPO·환전·특별 배당·PO 사용에 주문 예약금 반영. User/Wallet 잔고를 같은 트랜잭션에서 갱신.
- IPO 청약 취소·미배정 환불·발행자 대금 지급, Pre-IPO 전환과 보호예수 기간의 매도·양도 제한.
- 자사주 매입 시 매도자 주식 차감·대금 지급·체결 기록·자사주 수량까지 정산.
- 주주 매매를 공통 주문 엔진으로 연결. 양도는 실제 보유량을 이동하고, 주식 부여는 발행 가능 수량 내에서 처리. 주주 혜택과 목록도 실제 보유량 기준으로 조회.
- 환전 계좌 정보 저장, 관리자 권한 확인, 중복 처리 방지, 거절 시 PO 반환.
- 확인된 현금 잔액을 PO로 전환. 결제 확인 중복 적립을 차단하고 충전 화면의 가짜 결제 ID 생성 제거.
- 매매·PO 사용·배당의 PO 거래 원장 기록. 메뉴와 두 지갑 화면의 잔고·예약금·사용 가능 금액·내역 연결, 환전 수수료 10% 표시 통일.
- 주문 내역 페이지 이동, 상승·하락 종목 필터, 관심종목 알림의 원자적 저장.
- PostgreSQL 거래 트랜잭션에 공통 advisory lock을 추가해 여러 서버에서도 동일한 처리 순서를 사용하도록 구현.
- 기존 주문의 예약 방식 구분과 DB 이관 도구 추가. 구버전 주문은 새 엔진에서 자동 체결하지 않으며, 확인된 환불 금액과 근거를 받아 취소·정산.

## 앱 전체 완성도 보강

- 프로필 수정, 알림 설정, 로그인 기록, PO 송금 화면을 실제 API와 연결하고 내비게이터에 등록.
- 대회·전략·라이브·상품·NFT 상세 화면을 공통 디자인 체계로 구현하고 각 API의 참여·구매·상세 동작을 연결.
- PO 송금은 이메일 또는 사용자명으로 수신자를 찾고, 미체결 주문 예약금을 제외한 사용 가능 잔액만 원자적으로 이동하도록 구현. 양쪽 지갑 원장도 함께 기록.
- 웹과 네이티브의 확인창 동작 차이를 처리해 두 플랫폼 모두 송금 확인 후 실제 요청이 실행되도록 수정.
- 로그인 성공 기록을 저장하고 로그인 기록 화면에서 IP·기기·시간을 조회하도록 구현.
- 사용자 정적 라우트가 `/:userId`에 가로막히던 순서를 수정하고, 프로필·알림 설정 API를 연결.
- 관리자 거래 필드·집계 컬럼·발행자 연관관계, 뉴스 보유종목 조회, 본인인증 모델 연결 오류를 수정.
- 관리자 판별에서 이메일·고정 ID 예외를 제거하고 역할 기반 권한만 허용. 오류 목록·해결 API도 관리자 인증으로 보호.
- 회원가입 이메일을 정규화·검증하고, 브라우저 오류를 내부 오류 보고 API로 연결.
- 더 이상 사용되지 않는 목업 화면 2개를 제거하고, 전체 화면 이동 대상을 정적 감사하는 도구를 추가.

## 실행

```powershell
cd backend
npm ci
npm test -- --runInBand exchange.test.js
```

```powershell
cd frontend
npm ci
npm run build:web
```

격리된 수동 검증 서버는 `node backend/scripts/review-exchange.js`로 실행할 수 있습니다. 메모리 DB만 사용하며 기존 데이터에 접속하지 않습니다. 테스트용 계정과 토큰은 `tmp/review-session.json`에 저장됩니다. 프론트엔드는 `EXPO_PUBLIC_API_ORIGIN=http://127.0.0.1:5657`로 연결할 수 있습니다.

## 기존 DB 이관

대상 DB 백업과 원장 확인 후 아래 도구를 사용합니다. `--apply` 없이 실행하면 조회만 합니다.

```powershell
cd backend
node scripts/migrate-exchange.js
node scripts/migrate-exchange.js --apply --resolutions resolutions.json
```

`resolutions.json` 형식:

```json
[
  {
    "orderId": "확인한 기존 주문 UUID",
    "action": "cancel",
    "refundPO": 0,
    "evidence": "실제 차감 여부와 환불 금액을 확인한 원장 근거"
  }
]
```

`refundPO`는 추정하지 않고 실제 선차감 잔액을 확인하여 입력합니다. 근거 없는 기존 미체결 주문이 있으면 변경 전에 중단합니다. 처리 완료 주문을 재실행해도 다시 환불하지 않습니다. SQLite 누락 컬럼 추가와 이관 반복 실행을 메모리 DB에서 검증했습니다.

## 운영 적용 범위

- 이번 작업은 로컬 코드 변경이며 운영 배포는 하지 않았습니다.
- 이관 도구는 구현했지만 실제 운영 DB에는 적용하지 않았습니다. 기존 주문의 원장 근거와 실제 환불 금액은 운영 데이터에서 확인해야 합니다.
- PostgreSQL 실제 서버에서의 이관·다중 인스턴스 부하 검증은 이번 검증 범위에 포함되지 않습니다.
- 실결제 제공자·은행 지급·Google 로그인·뉴스 제공자·실기기 푸시 알림은 운영 자격 증명과 외부 서비스가 필요한 연동입니다. 이번 작업에서는 실제 외부 자금 이동이나 운영 자격 증명 검증을 실행하지 않았습니다.
- Android/iOS 실기기와 운영 PostgreSQL 환경은 실행하지 않았습니다. 웹 번들·Chromium·격리 SQLite 통합 환경에서 검증했습니다.
- 실제 거래소의 거래 시간, 결제 주기, 공매도·신용 거래 등 모든 제도를 복제한 것은 아닙니다.

의존성 복구 중 보관한 기존 파일은 `tmp/dependency-backups/`에 있습니다. 사용자 원본 데이터는 삭제하지 않았습니다.

이 환경의 프로젝트 드라이브에서 의존성 설치·정리가 매우 느려, 검증된 임시 설치 폴더에 `backend/node_modules`, `frontend/node_modules`를 연결했습니다. 소스는 원래 저장소에 유지됩니다. 임시 폴더를 정리하는 경우 의존성을 다시 설치해야 합니다. 테스트는 현재 작업 폴더의 소스를 동기화한 격리 검증 복사본에서 수행했습니다.
