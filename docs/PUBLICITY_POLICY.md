# 동의 전 인물 취급 정책

본인이 확인·동의하지 않은 실존 인물을 서비스에 노출할 때 지켜야 하는 규칙.
코드로 강제되는 지점을 함께 적어 두었으니, 이 규칙을 바꾸려면 해당 코드도 같이 봐야 한다.

> ⚠️ 이 문서는 법률 자문이 아니다. 런칭 전 엔터·퍼블리시티권 전문 변호사의 검토가 필요하다.

---

## 왜 필요한가

이전 구현은 동의 없는 실존 인물에 대해 다음을 만들었다.

- 가격이 붙은 종목 (`sharePrice` 기본 1,000 PO)
- 조작된 90일치 시세 이력
- 시가총액 순으로 정렬된 **공개** 목록 (`GET /virtual-celebrity/browse`, 인증 불필요)
- 실명 · 사진 · SNS 링크

즉 **동의하지 않은 사람들을 값으로 줄 세운 공개 페이지**였다.
"나무위키처럼 등록할 뿐"이라는 논리는 여기서 깨진다. 나무위키는 사람을 **서술**하지만,
가격은 사람을 **평가**한다. 그리고 하락은 그 자체로 사회적 평가 저하의 공표가 된다.

---

## 5대 규칙

### 1. 값을 매기지 않는다
동의 전에는 종목(`Stock`)을 **생성하지 않는다.** 가격·시가총액·등락률이 존재하지 않아야 한다.

- `virtualCelebrityController.createVirtualCelebrity` — `Stock.create` 없음, `marketCap: 0`
- `virtualCelebrityController.approveSuggestion` — 동일
- `virtualCelebrityController.approveClaim` — **여기서 처음** `Stock.create`

### 2. 얼굴을 쓰지 않는다
`profileImage` · `realName` · `newsKeywords` · `externalLinks` 를 저장하지도, 내보내지도 않는다.
실사진 대신 이니셜 플레이스홀더(`avatarInitial`)를 내려보낸다.

- `publicityGuard.IDENTITY_FIELDS`
- `publicityGuard.sanitizeProfile`

### 3. 줄을 세우지 않는다
전체 랭킹·백분위·하위 노출 금지. 상위 `PUBLIC_LIST_MAX`(30)명까지만 내보내고,
**전체 개수를 응답에 포함하지 않는다** — 클라이언트가 순위를 계산할 수 없어야 한다.

상위 노출은 괜찮다. 문제는 하위다. `전체 1,847명 중 1,846위` 는 조롱이 된다.

- `publicityGuard.PUBLIC_LIST_MAX`
- `listVirtualCelebrities` / `listSuggestions` — `pagination` 에 `total` 없음

### 4. 내려가지 않는다
기대지수(`expectationScore`)는 **단조 증가**한다. 감소 경로를 아예 두지 않는다.

내려갈 수 있으면 그 하락이 곧 "이 인물에 대한 기대가 떨어졌다"는 부정적 평가의 공표가 되어
주가와 똑같은 문제를 갖는다. 취소 API도, 반대표도 없다. **긍정 신호만 수집한다.**

- `publicityGuard.bumpExpectation` — 음수 delta 무시
- `upvoteSuggestion` — 취소 분기 없음
- `api.js` 의 `expectListing` — 대응하는 취소 함수 없음

### 5. 주어를 유지한다
표시되는 숫자는 **그 인물의 가치**가 아니라 **우리 이용자의 수요**다. 카피도 그래야 한다.

| ❌ 쓰지 말 것 | ✅ 쓸 것 |
|---|---|
| 인기 가상 셀럽 | 상장을 기다리는 중 |
| 선점 투자하고 본인 인수 시 수익! | 본인 확인이 완료되면 상장돼요 |
| ○○○ 1,000 PO ▼12% | 2,400명 대기 |
| 가상 주식으로 거래됩니다 | 본인 확인 전까지 거래되지 않습니다 |

## 거래 가드

동의 전에는 종목이 없으므로 원칙적으로 거래가 불가능하다.
`tradeGuard.checkTradable` 은 구버전 데이터를 막는 **2차 방어선**이다.

**이 가드에는 우회 스위치를 두지 않는다.** 과거 `ALLOW_UNCLAIMED_TRADING` 환경변수가 있었고,
값 하나로 동의 없는 인물의 거래가 전부 열리는 구조였다. 삭제했으며 다시 만들지 않는다.

---

## 기존 데이터 정리

구버전 플로우로 생성된 데이터는 아래 스크립트로 정리한다.

```bash
node scripts/migrateUnclaimedListings.js          # 미리보기
node scripts/migrateUnclaimedListings.js --write  # 적용
```

- 신원·사진 정보 제거, 시가총액 0으로
- 조작된 `PriceHistory` 삭제
- 주주가 없는 종목은 삭제
- **주주가 있는 종목은 삭제하지 않는다** — 유저 자산이 사라지므로 거래 중단(`delisted`) 후 수동 처리 대상으로 보고

주주가 있는 종목의 보유분 환불·정산 방침은 별도 결정이 필요하다.

---

## 아직 남은 것

- **미성년자 필터** 없음. 연습생·아동 청소년이 등록되면 사안이 완전히 달라진다.
- **삭제 요청 창구** 없음. 로그인 없이 접근 가능한 옵트아웃 경로와 처리 SLA가 필요하다.
- **검색엔진 색인 차단** 미적용. 웹 빌드 배포 시 `noindex` 필요.
- **일반인 차단** 없음. 공적 인물이 아닌 사람은 애초에 대상이 되면 안 된다.

## 코드 리뷰 체크리스트

동의 전 인물을 다루는 코드를 수정할 때 확인할 것.

- [ ] 동의 전 프로필에 `Stock` 을 만들지 않는가
- [ ] 공개 응답이 `sanitizeProfile` 을 거치는가
- [ ] 응답에 전체 개수·순위가 들어가지 않는가
- [ ] 기대지수를 감소시키는 경로가 없는가
- [ ] 카피의 주어가 "이용자의 수요"인가, "인물의 가치"인가
